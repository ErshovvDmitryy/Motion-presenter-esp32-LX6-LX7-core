КАК ПОЛЬЗОВАТЬСЯ СКРИПТАМИ ОБУЧЕНИЯ
====================================

Конвейер:  train_model.py -> convert_to_int8.py -> validate.py -> convert_to_header.py

Все скрипты запускаются ИЗ папки scripts (все создаваемые файлы появляются
рядом со скриптом). Перед запуском нужно поставить зависимости:

    pip install tensorflow numpy pandas scikit-learn matplotlib

СТРУКТУРА ДАТАСЕТА
------------------
Папка датасета содержит папки-классы, внутри каждого класса — CSV-файлы
движений. Каждая строка CSV = один семпл IMU (6 колонок: ax, ay, az, gx, gy, gz),
по 50 строк на файл (одно окно движения).

Пример готового датасета лежит здесь же: TEST3_50_10/
  + report.txt — отчёт о том, как он нарезан (окно, bias, количество жестов).

Имя класса-папки = имя класса модели. АЛФАВИТНЫЙ ПОРЯДОК создания списка
классов у скриптов по os.listdir, поэтому порядок классов в class_names.txt
может отличаться от порядка папок "вручную" — это нормально, главное
использовать именно тот порядок, который записан в class_names.txt.

Путь к датасету зашит в скриптах константой. Перед запуском поменяй на свой:

  train_model.py      ->  DATASET_PATH = "TEST_BIG_PACK_50_20"
  convert_to_int8.py  ->  dataset_path = "TEST_BIG_PACK_50_20"
  validate.py         ->  dataset_path = "TEST_BIG_PACK_50_20"
  analyz.py           ->  dataset_path = "TEST_BIG_PACK_50_20"

ШАГ 1. ОБУЧЕНИЕ МОДЕЛИ — train_model.py
----------------------------------------
    python train_model.py

  Создаёт:
    - gesture_model.h5         обученная Keras-модель
    - norm_params.npz          mean / std (параметры Z-score нормализации)
    - class_names.txt          ПОРЯДОК классов = порядок индексов на выходе модели!
    - training_history.png     график обучения
    - gesture_model.tflite     float32 TFLite

  В консоль выводятся параметры нормализации:
      Mean: [...]
      Std:  [...]
  Они понадобятся позже для MODEL_MEAN / MODEL_STDDEV в прошивке,
  их же можно вытащить из norm_params.npz.

ШАГ 2. КВАНТОВАНИЕ В INT8 — convert_to_int8.py
-----------------------------------------------
    python convert_to_int8.py

  Читает gesture_model.h5 + norm_params.npz + датасет (для калибровки берёт
  ~30% файлов, не более 500) и создаёт квантованную модель:

    - gesture_model_int8.tflite   int8 (для TFLM на ESP32)

ШАГ 3. ПРОВЕРКА КВАНТОВАНИЯ — validate.py
------------------------------------------
    python validate.py

  Сравнивает float32 (gesture_model.h5) и int8 (gesture_model_int8.tflite)
  на тестовой выборке:
    - точность float32
    - точность int8
    - разницу между ними (сильное расхождение = плохое квантование)
    - подробный отчёт по каждому классу (classification_report)
  Результаты сохраняет в model_comparison.txt.

  Ориентир: падение точности в пределах ~1-2% считается удачным квантованием.
  Если просадка больше — нужна проверка нормализации (analyz.py) либо
  переобучение / другой способ калибровки.

  Дополнительно можно посмотреть analyz.py — он оценивает диапазоны данных
  после Z-score и пригодность для int8 (уровни на единицу измерения).

ШАГ 4. ЭКСПОРТ В ЗАГОЛОВОК — convert_to_header.py
--------------------------------------------------
    python convert_to_header.py

  Читает gesture_model_int8.tflite и генерирует:

    - gesture_model_data.h   массив байтов + длина модели

  Скопировать его в прошивку (заменяя старый):

    Presenter/gesture_model_data.h

НАСТРОЙКА ПРОШИВКИ (Presenter/modelConfig.h)
---------------------------------------------
После смены модели синхронизировать единый конфиг:

  MODEL_WINDOW            число строк окна (вход модели),
                          для текущего пайплайна = 49
  MODEL_CLASSES           число классов = число строк в class_names.txt
  enum ClassId            порядок строго как в class_names.txt
                          (индекс элемента = номер строки в class_names.txt)
  CLASS_NAMES             имена классов (зеркало enum)
  MODEL_MEAN / STDDEV     параметры из norm_params.npz / вывода train_model.py
  gestureActionById()     какой класс -> какое действие устройства
                          (например SwipeLeft -> GEST_PREV_SLIDE)

Если MODEL_CLASSES и количество элементов в enum ClassId разойдутся —
прошивка не скомпилируется (static_assert). Это защита от ошибки.

Важно: классы на выходе модели нумеруются ПО ПОРЯДКУ СТРОК class_names.txt,
а не по имени. Если в новом обучении SwipeLeft оказался не 4-м — просто
переставь enum в modelConfig.h под новый порядок.
